# danburn testplan — 품질시험계획서만 따로(한글·엑셀)

사용자가 맡기는 일: `/danburn:start` 로 이미 만든 산출 폴더(또는 그 안의 `project.yaml`).
도구가 하는 일(`danburn test-plan`): project.yaml 에 적힌 내역서·블록·발주처 기준·현장 확인·KS 답으로 **관리계획서 8.11 과 같은 계산**을 한 번 하고, 품질시험계획서만 조립한다.
받는 결과: 같은 폴더의 `품질시험계획서.hwpx`(한글)·`품질시험계획서.xlsx`(엑셀)·`품질시험계획서.json`(시험 행 목록).
품질시험계획 대상 현장(start 판정)은 start 가 이미 계획서 전체를 `품질시험계획서.hwpx` 이름으로 썼으므로, 단독본은 `품질시험계획서(단독).hwpx/.xlsx/.json` 으로 나온다(덮어쓰지 않는다).

사용자가 준 인자: `$ARGUMENTS`

## 입력 정하기
- 인자가 폴더면 그 안의 `project.yaml` 을 쓴다. 파일이면 그 파일을 쓴다(이름이 달라도 된다).
- 비었으면(또는 글자 그대로 `$ARGUMENTS` 로 보이면) **한 번** 묻는다: "start 로 만든 산출 폴더(품질관리계획서.hwpx 와 project.yaml 이 있는 폴더)를 알려 주세요. 창에 끌어다 놓아도 됩니다." 기본 산출 폴더는 `~/Documents/danburn/<공사명>/` 이다.
- **project.yaml 이 없으면 여기서 질문을 만들지 않는다.** 시험계획서도 내역서 판정·현장 확인 답이 있어야 같은 값이 나온다 → `/danburn:start <도급내역서.xlsx>` 를 먼저 하도록 안내한다(끝나면 이 스킬로 돌아오면 된다).
- xlsx 도급내역서를 바로 줬다면 → start 로 안내. hwp·hwpx·pdf 계획서를 줬다면 → 검사이니 `/danburn:check` 로 안내.

## 준비 — 실행 파일 `<danburn>` 찾기
start 스킬의 "준비" 절과 같다(설치됨 `danburn` → 플러그인 `uvx --from "${CLAUDE_PLUGIN_ROOT}" danburn` → 저장소 `.venv` → `uvx --from git+https://github.com/yj5306yj/danburn danburn` 순서, `uv` 가 없으면 한 줄 설치 안내 후 멈춤, 출력은 UTF-8).

## 실행
```
<danburn> test-plan --project "<산출 폴더>/project.yaml"
```
- 기본 출력은 project.yaml 이 있는 폴더, 형식은 한글·엑셀 둘 다. 한 형식만: `--format hwpx` 또는 `--format xlsx`. 다른 폴더: `--out-dir "<폴더>"`(저장소 안이면 도구가 거부한다).
- 시험계획서만 개정할 때: project.yaml `개정이력` 에 `{개정: N, 일자: "YYYY. MM. DD.", 장: ["8.11"], 사유: "…"}` 한 줄을 더하고 `--revision N --date "YYYY. MM. DD."` 를 준다. 관리계획서 목차의 8.11 개정 번호와도 맞는다. 이력과 인자가 어긋나면 종료 2 이고 파일은 그대로다.
- 내역서를 바꿨으면 project.yaml `내역서.경로` 를 고치거나 `--boq "<새 내역서>"` 로 덮어쓴다(블록·발주처 기준도 `--block`·`--owner` 로 덮어쓸 수 있다).
- 종료 코드: 0 성공 / 2 입력 오류·개정 모순·**파일이 한글·엑셀에 열려 있음**(창을 닫고 다시) / 1 예상 못 한 오류(`DANBURN_DEBUG=1` 로 다시 실행한 출력을 이슈로 보고하게 안내, 임의로 우회하지 않는다).
- 출력은 **사람이 읽는 결과 화면**이다(check 와 같은 방식): 맨 위 `단번 품질시험계획서 — 공사명`, `만든 파일:`(한글·엑셀 이름과 폴더), `시험 N행 · 분야 · 4부`, `확인할 것`(앞 3가지와 나머지 개수), `(작성 필요) 칸:`(있을 때만), `(스캔첨부) 빈칸`, `다음 할 일:` 줄. 인터넷 없이 하려면 `--offline`.
- 자세한 값이 필요하면(파일 경로 확인·확인할 것 전부) 같은 명령에 `--json` 을 붙여 따로 돌린다: `hwpx`·`xlsx`·`json` 경로(안 만든 형식은 null), `test_plan`(`rows`·`disciplines`·`scan_attachments`·`revision`·`date`·`boq`·`block`·`owner`), 그 밖은 start·plan 요약과 같다(`warnings`·`needs_confirmation`·`basis_check` 등).
- 종료 0 만 믿지 말고 `만든 파일:` 줄의 폴더에 그 파일들이 이번 실행에서 생겼는지 확인한다.

## 끝나면 — 결과 화면 그대로
- **도구의 결과 화면을 고치거나 줄이지 말고 코드 블록으로 그대로 보여 준다.** 도구 화면이 곧 사용자에게 보이는 결과다(랜딩 영상도 이 화면).
- 그 아래에 **한 줄만** 덧붙인다: 가장 먼저 할 일. 보통 `확인할 것` 첫 줄(발주처 기준 필요·규칙 없음이면 "그 자재의 시험계획은 발주처 기준으로 사람이 써야 합니다", 제조사 1곳 계산이면 "제조사가 여럿인 자재는 project.yaml 제조사수에 적고 다시 돌리세요"). 확인할 것이 없으면 `(작성 필요) 칸` 채우기, 그것도 없으면 스캔본 붙이기.
- 사용자가 `(작성 필요)` 칸 값을 말하면(예: "공사위치는 ○○로 해 줘") project.yaml 의 **그 키 값만** 바꾸고(파일 쓰기 도구로, 들여쓰기·다른 키는 그대로) 같은 `test-plan` 명령을 다시 돌려 새 결과 화면을 보여 준다. 사람이 한글에서 직접 고친 내용은 다시 돌리면 덮어쓰인다는 것을 그때 한 번 알린다. 계산 입력(내역서·현장_확인·KS_인증·제조사수)은 사용자가 분명히 말한 값만 적는다.
- 판정·횟수·기한을 새로 만들지 않는다. 구성(1. 개요 / 2. 품질시험 및 검사계획 — 시험방법 칸 포함 / 3. 품질시험 시설 / 4. 품질관리자 배치계획)을 물으면 설명한다.
- 초안이며 품질관리자가 현장 조건(발주처 특기시방·감리 지시)을 확인해 확정한다 — 화면 마지막 줄에 이미 있으므로 되풀이하지 않아도 된다. 한글(맥은 무료 한글 Viewer)과 엑셀에서 열어 확인하라고 안내한다.

## 개인정보 — start 스킬과 같다
- 증빙(자격증·경력증명서·재직증명서)은 **파일을 열거나 넣지 않는다.** 도구도 빈칸만 만든다. 증빙 이름·경로를 대화에 옮겨 적지 않고 개수만 말한다.
- 증빙을 붙일 사람에게 "주민등록번호 뒷자리를 가렸는지" 한 번 확인한다.
- 산출물은 저장소 밖 산출 폴더에 둔다. 내역서·산출물을 외부 서비스에 올리지 않는다.

## 하지 말 것
- 질문을 새로 만들거나 도구의 계산·횟수를 손으로 고쳐 "맞춰" 보고하지 않는다. 관리계획서 8.11 과 값이 다르면 그대로 알리고 같은 project.yaml 로 두 명령을 다시 돌리게 한다.
- 스캔첨부 칸을 다른 파일로 채우지 않는다.
