# danburn check — 기존 계획서의 인용 기준이 현행인지 검사

사용자가 맡기는 일: 가지고 있는 품질관리계획서 파일 하나(.hwp .hwpx .pdf, 남이 만든 것도 됨).
도구가 하는 일: 본문에서 업무지침 고시 번호·계획서 작성(개정)일·건설기술 진흥법령·KCS/KDS/LHCS 인용을 찾아 현행과 비교한다. 업무지침이 개정되면 기존 계획서는 재수립 대상이 될 수 있어서다.

검사할 계획서: `$ARGUMENTS`
- 위가 비어 있으면(또는 글자 그대로 `$ARGUMENTS` 로 보이면) 사용자에게 **한 번** 묻는다: "검사할 계획서 파일(.hwp .hwpx .pdf) 경로를 알려 주세요. 창에 끌어다 놓아도 됩니다." 답을 받기 전에는 실행하지 않는다.
- 경로에 공백이 있으면 따옴표로 감싼다. 파일이 없으면 경로를 다시 묻는다(추측해서 찾지 않는다).
- xlsx 도급내역서를 줬다면 검사가 아니라 새로 만들기다 — start 스킬(`/danburn:start`)로 안내한다.

## 준비 — 실행 파일 `<danburn>` 찾기 (먼저 OS·셸 확인)
- 이 스킬은 **로컬 파일을 읽고 명령을 실행할 수 있는 에이전트**에서만 동작한다. 그런 도구가 없는 대화 창이면 처음에 그 사실을 알리고, 명령 실행이 되는 환경(CLI 에이전트 등)을 안내한다. 글만 읽고 설치됐다고 말하지 않는다.
- 아래 순서로 처음 되는 것 하나를 `<danburn>` 으로 쓴다. `<danburn> --help` 가 나오면 된다.
  1. **플러그인으로 설치됨** — 플러그인 폴더가 `${CLAUDE_PLUGIN_ROOT}` 이다(Claude Code 가 실제 경로로 바꿔 넣는다. 글자 그대로 `${…}` 로 보이면 플러그인이 아니니 건너뛴다). 설치된 플러그인 판과 같은 코드를 쓴다:
     `uvx --from "${CLAUDE_PLUGIN_ROOT}" danburn`
  2. **저장소 안** — `pyproject.toml` 과 `src/danburn/` 이 있는 폴더(`<저장소>`)에 가상환경이 있으면:
     맥·리눅스 `<저장소>/.venv/bin/danburn`, Windows `<저장소>\.venv\Scripts\danburn.exe`
  3. **둘 다 없음** — 공개 저장소에서 바로:
     `uvx --from git+https://github.com/yj5306yj/danburn danburn`
- 1·3 은 `uv` 가 필요하다. `uv --version` 이 안 되면 **여기서 멈추고** 사용자에게 한 줄 설치를 안내한 뒤 새 터미널에서 다시 하자고 한다:
  - 맥·리눅스: `curl -LsSf https://astral.sh/uv/install.sh | sh`
  - Windows(PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
- 처음 `uvx` 실행은 파이썬과 의존성을 받느라 몇십 초 걸린다(다음부터는 캐시). 네트워크가 막혀 있으면 2(저장소 `.venv`)를 쓴다.
- 출력은 UTF-8 이다(파이프로 받아도 도구가 UTF-8 로 쓴다). 실행기에서 출력을 UTF-8 로 읽는다. `PYTHONIOENCODING` 을 cp949 로 넣지 않는다(넣으면 한글 기호에서 멈춘다). PowerShell 5.1 은 `&&` 를 못 쓴다 — 명령을 한 줄씩.

## 실행과 결과 전하기
1. 실행: `<danburn> check "<계획서 파일>"` (`--json` 없이 — 사람이 읽도록 만든 결과 화면이 나온다).
   **그 결과 화면을 고치거나 줄이지 말고 코드 블록으로 그대로 보여 준다**(맨 위 `결과:` 줄, `[개정됨]`·`[확인 필요]`·`[현행]` 항목과 각 `할 일`·링크, 끝의 알림 줄까지). 도구 화면이 곧 사용자에게 보이는 결과다 — 랜딩 영상도 이 화면이다.
   그 아래에 한 줄만 덧붙인다: 가장 먼저 할 일(보통 첫 `[개정됨]` 항목의 할 일). 판정·기한을 새로 만들지 않는다.
   JSON 이 필요하면(예: 여러 파일을 표로 모을 때) 같은 명령에 `--json` 을 붙여 따로 돌린다.
2. 종료 코드: 0=찾은 인용이 모두 현행, 3=개정·폐지된 인용 있음, 4=판정 못 함(인용을 못 찾음·현행 확인 실패), 2=파일을 못 읽음 — 도구가 낸 안내를 그대로 전한다. 배포용·암호 HWP 는 한글에서 PDF 로 저장해 다시, 스캔 PDF(글자 없는 그림)는 원본 한글 파일(hwp·hwpx)로 다시 하도록 안내(글자 인식은 하지 않는다). 종료 1(`예상하지 못한 오류`)이면 `DANBURN_DEBUG=1` 로 다시 실행한 출력을 이슈로 보고하도록 안내하고 임의로 우회하지 않는다.
3. 결과 화면이 매우 길면(항목 수십 개) `[개정됨]` 항목은 모두 그대로 두고, `[현행]` 줄만 "현행 N건(생략)"으로 줄여도 된다 — 그때는 줄였다고 적는다.
4. 인터넷 없이 내장 기준표로만 보려면 `--offline`.

- 결과는 알림이다. 계획서를 고치기 전에 공식 원문(법제처·국가건설기준센터)으로 확인하라고 적는다. 스킬이 판정을 바꾸거나 기한을 지어내지 않는다.

## 개인정보
- 계획서 파일은 사용자 컴퓨터에서만 읽는다. 복사·업로드·요약본 저장을 하지 않는다. 내용을 네트워크로 보내지 않는다(현행 확인 요청에는 공개 법령 경로만 들어간다).
- 발췌(`where`)는 이 대화 안에서만 보여 주고 다른 파일·서비스로 옮기지 않는다. 결과 화면 밖(덧붙이는 말·다른 파일)에 계획서 속 사람 이름·연락처를 옮겨 적지 않는다.

## 하지 말 것
- 도구의 판정을 손으로 고쳐 "맞춰" 보고하지 않는다. 이상하면 그대로 보여 준다.
- 계획서를 고쳐 주겠다며 파일을 바꾸지 않는다. 이 스킬은 검사만 한다.
