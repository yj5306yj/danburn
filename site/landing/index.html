왜
업무지침이 개정되면 기존 계획서는 다시 세워야 할 수 있습니다.
찾는 것업무지침 고시 번호·계획서 작성일 · 건설기술 진흥법령 판 · KCS·KDS·LHCS 연도판과 폐지 · 옛 법령 이름
기준최신 법령·기준으로 계속 갱신합니다(확인일 표시)
개인정보계획서 내용은 컴퓨터 밖으로 보내지 않음(인터넷은 현행 업무지침 번호 확인에만)

새로 만들기 — 무엇을 넣고 무엇이 나오나

  1. 1 · 넣는 것

    도급내역서(xlsx)

    지급·사급 내역 시트가 있는 공동주택 도급내역서. 읽을 수 있는 양식인지 먼저 확인합니다.

  2. 2 · 답하는 것

    질문 몇 개

    발주자(공공·민간), 공사 규모, 현장 이름과 사람. 답으로 적용 법(품질관리계획 대상, 품질관리자·시험실 기준)을 판정합니다.

  3. 3 · 나오는 것

    품질관리계획서.hwpx

    한글에서 열리는 계획서 한 권과, 사람이 확인할 것 목록.

계획서에 들어가는 것

1~10장 틀

「건설공사 품질관리 업무지침」 별표1 순서의 33절. 절마다 개요 칸·업무 분장표·업무 흐름표, 기록 양식 42종. 문장은 모든 현장에 같은 공통 초안이라 현장에 맞게 고쳐 씁니다.

8.11 시험계획 계산

내역서 물량으로 별표2의 시험종목·빈도·계획횟수를 계산하고 행마다 산출근거를 적습니다. 규칙이 없는 자재는 따로 표시합니다.

법 판정

건설기술 진흥법 시행령 제89조와 시행규칙 별표5로 계획 종류와 품질관리자·시험실 기준을 판정해 1장과 8.11에 적습니다.

비고결과는 제출 전 검토용 초안이며, 확정은 품질관리자가 합니다. 법정 서식 충족이나 승인을 보장하지 않습니다. 만들 때는 한글(한컴오피스)이 필요 없고, 제출 전에는 한글로 열어 확인합니다. 맥에서 만들고 확인했으며 Windows는 새 파이썬 환경에서 생성과 한글 열기까지 확인했습니다.

설치와 실행

처음이면 3단계

  1. 1 · 터미널 열기

    맥: Spotlight(⌘ Space)에서 “터미널”
    윈도우: 시작 메뉴에서 “PowerShell”

  2. 2 · uv 설치 한 줄

    맥

    curl -LsSf https://astral.sh/uv/install.sh | sh

    윈도우

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    끝나면 창을 닫았다 다시 엽니다.

  3. 3 · 명령 붙여넣기

    두 가지 일 카드의 터미널 명령을 복사해 붙여 넣고 Enter. 질문에 답하면 됩니다.

터미널에서 한 줄

uvx --from git+https://github.com/yj5306yj/danburn danburn start

기존 계획서 검사는 끝의 start 대신 check 계획서.hwp.

계획서.hwp 자리에 내 파일 — 파일을 창에 끌어다 놓으면 경로가 들어갑니다

uv가 있어야 합니다. 계속 쓸 거라면 pipx install git+https://github.com/yj5306yj/danburn 후 danburn start.

AI 에이전트에게 맡기기

Claude Code에서는 플러그인으로 설치합니다(터미널에서 두 줄, 한 번만).

claude plugin marketplace add https://github.com/yj5306yj/danburn
claude plugin install danburn@danburn

그다음 /danburn:start(새로 만들기) 또는 /danburn:check 계획서.hwp(기존 계획서 검사)를 칩니다. 에이전트가 도구의 질문을 한 번에 하나씩 그대로 묻고 결과를 전합니다.

도구 실행에는 uv가 필요합니다. Codex 같은 다른 에이전트는 작업 지침에 저장소의 skills/start/SKILL.md(새로 만들기)나 skills/check/SKILL.md(검사)를 읽으라고 적고 “이 폴더의 도급내역서로 품질관리계획서 만들어 줘”처럼 말합니다.

만든 사람

LH 공공주택 현장 품질관리자 출신 개발자가 만들었습니다

착공 전에 품질관리계획서를 쓰고, 공사 내내 고쳐 냈습니다. 기준을 찾고, 바뀌는 내역서로 수량을 다시 셈하고, 긴 한글 문서를 손보는 데 한 번에 한두 달씩 걸렸습니다.

그 일을 내역서 한 번 넣는 것으로 줄이려고 만든 도구입니다. 가장 공들인 곳은 8.11 검사 및 시험, 모니터링입니다.

감사와 출처

아래 공개 소프트웨어와 공개 자료 덕분에 만들 수 있었습니다. 전체 목록과 라이선스는 저장소의 NOTICE.md에 있습니다.

한글 문서·파일 처리 오픈소스

  • python-hwpx Apache-2.0 한컴 없이 HWPX를 만들고 검사
  • rhwp MIT 한컴 없이 HWPX를 PDF로 그려 쪽 모양 확인(개발 도구)
  • lxml BSD-3-Clause HWPX 속 XML 처리
  • openpyxl MIT 도급내역서 xlsx 읽기
  • PyYAML MIT 규칙·현장 정보 읽기
  • olefile BSD-3-Clause 기존 계획서 HWP 읽기
  • pypdf BSD-3-Clause 기존 계획서 PDF 읽기
  • uv Apache-2.0 OR MIT 설치를 한 줄로

법령·기준 공개 자료

  • legalize-kr/admrule-kr, 행정규칙 공개 미러(업무지침 현행 판 확인)
  • 국가법령정보센터 · 공동활용 API, 업무지침 별표1·별표2와 건설기술 진흥법·시행령·시행규칙 원문
  • 국가건설기준센터(KCSC), KCS·KDS·LHCS 현행판 확인(내장 기준표)
  • 공공데이터포털, 공개 법령·기준 API 조사
  • 한컴 HWP/OWPML 공개 문서, HWP·HWPX 문서 구조 참고

본 제품은 한글과컴퓨터의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.
