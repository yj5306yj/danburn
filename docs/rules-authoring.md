# 자재 규칙 작성 안내 (data/rules/*.yaml)

규칙 파일은 **추가만 하면 자동 등록**된다(`load_rules`가 폴더의 모든 yaml을 읽는다). 한 파일 = 한 자재(`material`).

## 출처 원칙
- 시험종목·방법·빈도는 **「건설공사 품질관리 업무지침」 별표2 원문**(`.cache/law/byeolpyo2.pdf`, 현행 제2026-360호와 내용 동일)에서만 가져온다. 쪽 번호를 `basis`에 적는다.
- 조문 전문을 옮기지 않는다. 번호·항목명·요약만.
- 실무 관행(계획서에서 흔히 쓰는 표기·묶음)은 `basis`를 `"실무 관행 — …"`으로 시작해 구분한다.
- 실제 현장 계획서·정답지를 보지 않는다(누출 방지). 실자료 수치·실명 금지.

## 형식
```yaml
material: concrete_brick            # 영문 소문자 키(파일명과 같게: concrete_brick.yaml)
label: 콘크리트벽돌                   # 8.11 시험항목에 나오는 이름
work: 조적공사                        # 선택. 8.11 공종 칸 기본값(아래 “공종 칸” 참고)
basis_version: "국토교통부고시 제2026-360호(2026-07-08 시행) 「건설공사 품질관리 업무지침」 별표2"
index_keys: [concrete_brick]        # data/byeolpyo2_index.yaml 의 종별 key(여럿 가능). 동의어가 자동으로 매칭에 쓰인다
match:                              # 선택. 없으면 색인 동의어를 쓴다
  names: [콘크리트벽돌]
  units: [ea]                       # 정규화 단위(m3, m2, ton, m, ea …). 도급내역서 단위와 맞아야 행이 잡힌다
  exclude: [쌓기, 설치]              # 노무 행 제외 단어(색인 is_labor 와 별개로 필요할 때)
  names_generic: [거푸집]             # 선택. 아래 “일반 이름 + 규격” 참고(spec_names 와 함께)
  spec_names: [합판]
ks_mark: true                       # 종별 괄호에 KS 가 있으면 true → KS 칸 ◎
ks_count: none                      # 묶음 행 KS 제품: none=시험 없이 ◎(시행령 91조 면제, 산출근거 'KS자재'), makers=제조사 수×1회
order: 30                           # 8.11 안 순서(철근 10, 콘크리트 20)
group_tests: true                   # 시험을 규격당 한 행으로 묶어 적는 자재(대부분)
group:
  frequency: "제조회사별, 제품규격별"   # 8.11 시험빈도 칸 문구(짧게)
  basis: "별표2 3. 건축 가. 조적 콘크리트벽돌(KS F 4004) (PDF p.36)"
tests:                              # 별표2 그 종별의 시험종목을 빠짐없이
  - test_type: 압축강도
    method: "KS F 4004"
    where: 외부                       # 현장 | 외부 | KS
    frequency: {per_qty: null, unit: null, text: "제조회사별, 제품규격별", minimum: 1}
    basis: "별표2 … 압축강도 (PDF p.36)"
    conditions: "원문 조건 요약. 해석이 필요하면 '해석 필요: …'"
```
- 물량 비례 빈도(예: 1,000㎡마다)는 `per_qty`·`unit`에 숫자로. 묶음 행에서 KS 가 아니면 ⌈물량/빈도⌉×제조사 수로 계산된다.
- 레미콘처럼 시험마다 행을 따로 쓰는 자재만 `group_tests: false`.

## 검증(각 워커)
- 자기 테스트 파일 `tests/rules/test_<묶음>.py`: 각 yaml 로드, 합성 BoqLine(색인 동의어 품명 + 올바른 단위)이 그 규칙으로 잡혀 8.11 행이 나오는지, KS 면제면 ◎·'KS자재', 비KS 물량 빈도면 횟수 계산.
- `.venv/bin/python -m pytest -q` 전체 통과, `scripts/check-names.sh` 0건(식별어 목록 파일은 열지도·도구 입력으로도 쓰지 않는다 — 스크립트 실행만).

## 공종 칸(선택, `work`)
8.11 공종 칸은 이 순서로 채운다.
1. 그 자재를 낸 도급내역서 행들의 구분 경로(`BoqLine.section`)에서 가장 깊은 공종 제목(번호 떼고, `…공사`·`…공`으로 끝나는 것). 분야(건축공사 등)·부위(상부공사·기초공사)·동·블록·층·사업명은 건너뛴다. 행마다 다르면 **수량 가중 다수결**(같으면 먼저 나온 것).
2. 1이 없으면 규칙의 `work`.
3. 둘 다 없으면 빈 칸 — 요약의 `work_missing` 에 센다.

`work` 값은 별표2 절 이름(예: `나. 방수공사` → `방수공사`)을 기본으로 하되, 절이 `기타`·`가설기자재`이거나 실무 공종과 다르면 실무 이름으로 적는다(예: 도자기질 타일 → `타일공사`, 건조시멘트모르타르 → `미장공사`, 도로공사 절의 포장 자재 → `포장공사`, `토공사 및 기초공사` → `토공사`). LH 규칙은 부록 자재 분류(Ⅱ.n)를 공종으로 옮긴다(창호재 및 유리 → `창호공사`, 방수재 및 실링재 → `방수공사` 등). 확실하지 않으면 비워 둔다.

## 일반 이름 + 규격(선택, `names_generic`·`spec_names`)
품명이 일반 이름뿐이고 자재가 **규격 칸**에만 적힌 행을 잡는다. 예: 품명 `거푸집 (토목,조경)`, 규격 `합판6회, 간단` → 거푸집용 합판.
- 조건: `names` 가 품명에 없을 때, 품명에 `names_generic` 중 하나가 있고 **규격**에 `spec_names` 중 하나가 있으면 이 규칙. 둘은 함께 적는다(하나만 있으면 로더 오류).
- `units`·`exclude`(품명 기준)·시공 행 규칙은 그대로 적용된다. 규격에 자재 이름이 “대체”처럼 다른 뜻으로 들어가는 재질(알루미늄·유로폼 거푸집 등)은 `exclude` 로 막는다.
- `names` 로 맞은 다른 규칙이 있으면 그쪽이 먼저다(일반 이름 길이로 겨룸). 이 필드가 없는 규칙은 규격 칸을 보지 않는다.

## 단위 환산(선택)
빈도 단위와 내역 단위가 다르면 `unit_factors`로 환산한다(합산 전에 적용).
곱을 `0` 으로 두면 "이 단위 행은 자재가 들어 있음만 알리고 수량은 환산하지 않는다"는 뜻이다(예: `m2: [ton, 0]` — ㎡ 시공 행 안의 건조모르타르). KS 제품이면 ◎ 행이 수량 `-` 로 나오고, 물량 빈도면 횟수를 만들지 않고 "수량 확인 필요"로 표시한다.
```yaml
unit_factors:
  천매: [ea, 1000]     # 내역 단위: [환산 단위, 곱]
  포: [ton, 0.04]      # 40kg 포
```

## 발주처 기준 규칙(선택)
LH 등 발주처 전문시방서의 시험 기준은 `owner: LH`를 붙인 규칙으로 만든다(`--owner LH` 일 때만 켜짐).
- 출처: LHCS 10 40 00:2020 「시험」 부록 「품질시험 및 검사기준」(한국토지주택공사, KCSC 공개, 공공데이터포털 이용허락범위 제한 없음). `basis`에 부록 절(예: Ⅱ.11)과 종별을 적는다. 원문 문장·표 전체를 옮기지 않고 종별·시험종목·빈도 사실만.
- `basis_version: "LHCS 10 40 00:2020(2020-12-09) 부록 「품질시험 및 검사기준」"`
- 별표2 밖 목록(`data/extra_catalog.yaml`)의 항목을 다루면 `extra_keys: [sealant]`처럼 적어 “발주처 기준 필요” 경고에서 뺀다.
- 파일 이름은 `lh_<key>.yaml`.

## 규격 묶음(선택, `spec_group`)
기본은 규격마다 8.11 행이 하나씩 생긴다(레미콘 `25-24-150`, 철근 `SD400 D13` — 원본 관행이므로 이 둘에는 쓰지 않는다).
창호 부호·관 지름·두께·색처럼 규격이 수십 개로 쪼개져도 시험이 달라지지 않는 자재는 묶는다.
```yaml
spec_group: all                     # 규격을 모두 합쳐 한 행. 규격 칸 표시는 '규격별'
spec_group: {label: 전체}            # 한 행, 표시만 바꿈
spec_group:                         # 정규식 그룹별(규격 먼저, 없으면 품명에서 찾음. 대소문자 무시, 그룹은 대문자로)
  pattern: "/(F?S?SD|AW)|(방화문)"   # 창호 부호·종류
  label: "{1}{2}"                   # 안 맞은 그룹은 빈칸. 기본 "{1}"
  other: 기타                        # 규격·품명 모두 안 맞을 때(기본 '기타')
```
- 물량은 **같은 단위끼리만** 합친다(단위가 다르면 단위별 행, 예: 보온재 ㎡·m).
- 묶은 행의 산출근거·횟수는 묶음 행 계산을 그대로 탄다: KS ◎면 'KS자재', 물량 비례 빈도면 **합계 물량**으로 ⌈물량/빈도⌉×제조사 수, 문구형(제조회사별)이면 제조사 수(기본 1, `--makers`)×1회. 원행 추적(sources)은 합쳐진다.
- 원문이 종류별로 시험종목을 달리 적는 자재(석고보드 방수·방화 등)는 `all` 대신 종류 `pattern`으로 나눈다.
- 비KS(`--non-ks`)에서 빈도가 '제품규격별'인 자재를 묶으면 규격 수만큼의 시험이 한 줄로 줄어든다 — 비KS 현장이면 묶음을 풀거나 제조사 수로 보정한다.
